# PRD: 登录功能

## 1. 背景

用户需要通过邮箱和密码登录系统以访问受保护资源。当前项目仅有 skeleton，
尚无任何登录能力。本次需求实现一个最小可用的登录功能，包含"记住我"选项，
让用户在关闭浏览器后仍能保持登录状态，减少重复登录的摩擦。

## 2. 用户故事

- 作为访客，我希望通过邮箱和密码登录，以便访问我的账户。
- 作为用户，我希望勾选"记住我"后即使关闭浏览器也保持登录状态，以便不必每次重新输入凭据。
- 作为用户，我希望输入错误的邮箱或密码时看到清晰的错误提示，以便知道哪里出了问题。
- 作为用户，我希望在未勾选"记住我"时关闭浏览器即自动登出，以便在公共设备上保护账户安全。

## 3. 验收标准

- [ ] 登录页面包含邮箱输入框、密码输入框、"记住我"复选框和"登录"按钮。
- [ ] 用户输入正确邮箱 + 密码，点击登录后成功登录，页面显示已登录状态。
- [ ] 用户输入错误密码，登录失败，显示"邮箱或密码错误"提示（不透露具体是邮箱还是密码错误）。
- [ ] 用户输入无效邮箱格式（如缺少 @），前端阻止提交并提示"请输入有效的邮箱地址"。
- [ ] 密码和邮箱均不为空时才允许提交登录。
- [ ] 勾选"记住我"登录后，关闭并重开浏览器，用户仍处于登录状态。
- [ ] 不勾选"记住我"登录后，关闭并重开浏览器（session 过期），用户需重新登录。
- [ ] 登录成功后，服务端返回可用于后续请求认证的 token/session。
- [ ] 密码在传输和存储过程中不以明文形式出现。
- [ ] 连续登录失败 5 次后，该账号在 15 分钟内被锁定（返回"登录尝试过多，请稍后再试"）。

## 4. Scope（范围）

### In scope（v0.1.0 做）

- 邮箱 + 密码登录页面与接口
- "记住我"功能（长时效 vs 短时效 session/token）
- 基本输入校验（邮箱格式、非空）
- 登录失败错误提示（统一模糊提示，不区分邮箱/密码错误）
- 登录限流（单账号连续失败锁定）
- 密码安全存储（哈希处理，不存明文）
- 登录态校验接口（前端可通过该接口判断是否已登录）

### Out of scope（v0.2+ / 不做）

- 用户注册功能（本次假设用户数据已存在）
- 密码找回 / 密码重置功能
- 第三方登录（OAuth / SSO）
- 多因素认证（MFA / OTP）
- 邮箱验证流程
- 角色权限管理（RBAC）
- 管理员后台用户管理
- 登出功能（可作为附带实现，但不作为本次验收重点）

## 5. UI/UX 期望

- **页面布局**：居中卡片式登录表单，简洁清晰。
- **交互流程**：
  1. 用户打开 `/` 或 `/login`，看到登录表单。
  2. 填写邮箱、密码，可选勾选"记住我"。
  3. 点击"登录"按钮：
     - 校验失败 → 表单上方显示红色错误提示，不跳转。
     - 校验成功 → 页面切换为已登录状态（显示"已登录"+ 用户邮箱），无需跳转。
  4. 已登录用户再次访问 `/login`，直接显示已登录状态。
- **错误提示**：统一在表单上方显示，文字清晰，不暴露具体失败原因。
- **"记住我"**：复选框默认不勾选，文案"记住我"。

## 6. 非功能需求

- **性能**：登录接口响应时间 < 200ms（正常负载下）。
- **安全**：
  - 密码使用 bcrypt（或同等强度的哈希算法）存储，不存明文。
  - 登录接口走 HTTPS（生产环境要求；开发环境不强制）。
  - "记住我" 的长效 token 需有合理过期时间（建议 30 天）。
  - 非"记住我"的 session 过期时间应与浏览器会话一致（关闭浏览器即失效）。
  - 登录限流：单账号 5 次失败后锁定 15 分钟。
- **兼容性**：支持 Chrome 100+、Firefox 100+、Safari 15+、Edge 100+。
- **可维护性**：代码结构清晰，登录逻辑与展示逻辑分离。
